# T2.2: Ticker input + XBRL cross-check badges

## Goal

1. A user can type a US ticker, choose one of the company's recent 10-K filings, and get the analysis
   without finding a PDF.
2. In that flow, every **mapped** value shows a badge: **matches SEC XBRL**, **differs from SEC XBRL**
   (showing both numbers), or **no XBRL fact**.

## Why

Finding a PDF is the biggest friction in the demo. The cross-check turns the tier-1 eval into a live,
per-number proof inside the product.

## Prerequisites

T2.1 merged. `SEC_USER_AGENT` is available locally (and in Streamlit secrets if it is enabled on the hosted app).

## Read first

- `src/fincopilot/sources/edgar.py`, `src/fincopilot/sources/render.py` (T1.1)
- `evals/concept_tags.py`, `evals/truth_xbrl.py`, `evals/score.py` (T1.1/T1.2)
- `app.py` in full (sidebar, upload flow, caching, tabs), `src/fincopilot/views.py`, `tests/test_app.py`
  (how the app is tested, e.g. Streamlit `AppTest`, and how dependencies are faked)
- `EXECUTION_RULES.md` §1 (invariant 1 applies directly here) and §6

## Invariant reminder (the most important line in this file)

The XBRL value is **never** displayed *as* the value, never fills a missing value, and never feeds a ratio,
rule or narrative. It appears only inside the badge, as a check. The analysis must be byte-identical with the
cross-check on or off.

## Step 0: hosted feasibility spike (time-box: 2 hours, decision recorded in the log)

The ticker flow needs Chromium to render the filing. Try it on Streamlit Community Cloud: add `chromium` to a
`packages.txt`, have `render.py` use the system Chromium executable if present
(`executable_path` from env `FINCOPILOT_CHROMIUM`), and deploy to a **test** app, not the main demo.

- Works (renders a 10-K in < 60 s, peak memory OK) → ticker flow enabled on hosted.
- Fails → ticker flow is **local only**. The UI hides it when rendering is unavailable, and the README says so.

Either outcome is fine. Record which one, with evidence. Do not spend longer than the time-box.

## Design (fixed)

### Refactor first (no behaviour change)

Move the reusable XBRL logic out of `evals/` into the package so the app can use it:

- `evals/concept_tags.py` → `src/fincopilot/sources/xbrl_tags.py`
- `evals/truth_xbrl.py` → `src/fincopilot/sources/xbrl_truth.py`
- The tolerance comparison (the correct/sign/tolerance core of `score.py`) → a pure function in a new
  `src/fincopilot/crosscheck.py`: `compare(app_value: Decimal, scale: Scale, accepted: tuple[Decimal, ...],
  sign_agnostic: bool) -> CompareOutcome` (`MATCH | SIGN_MISMATCH | DIFFERS`).
- `evals/` imports these. **The dev eval must produce identical results after the refactor.** Commit the
  refactor alone, run the gate, then build features.

### `crosscheck.py`

```python
class Badge(Enum): MATCH = "match"; DIFFERS = "differs"; NO_XBRL = "no_xbrl"; NOT_SCORED = "not_scored"

@dataclass(frozen=True, slots=True)
class CrossCheck:
    concept: str
    end_year: int
    badge: Badge
    xbrl_values: tuple[str, ...]   # Decimal strings; empty unless DIFFERS or MATCH
    tags: tuple[str, ...]

def cross_check(result: AnalysisResult, truth: list[TruthValue]) -> dict[tuple[str, int], CrossCheck]
```

- Only mapped values (`result.mapping.values`) get MATCH/DIFFERS/NO_XBRL. Derived values and concepts not in
  the tag table get `NOT_SCORED`.
- `SIGN_MISMATCH` shows as `DIFFERS`, with the detail "same magnitude, opposite sign".
- No types added to `types.py`, and `AnalysisResult` is unchanged.

### UI (Streamlit)

- Sidebar: a new "Analyse by ticker (US)" section **above** the uploader, shown only when rendering is available
  and `SEC_USER_AGENT` is set.
  - Ticker input, validated with `^[A-Za-z][A-Za-z.\-]{0,9}$`; anything else gets an inline error and no request.
  - A "Filing" select listing up to 5 recent 10-Ks as `FY<report year> (filed <date>)`.
  - An "Analyse" button, then a staged status: fetching filing → rendering to PDF → analysing → cross-checking.
- The rendered PDF bytes then go through **exactly the same path as an upload** (same cache, same tabs).
  No second analysis path.
- **Values tab**: a new column "SEC XBRL", with ✓ match, ⚠ differs (tooltip or expander showing the XBRL value(s),
  tag, and the sentence "The figure shown is read from the filing document; the SEC data is shown only as a
  check."), — for no XBRL fact, and blank for not scored.
- **Provenance tab**: the same badge next to the selected figure.
- A header line: "Cross-checked N values against SEC XBRL: A match, B differ, C have no XBRL fact."
- Failures (`SourceError`, `RenderUnavailable`) show a plain message and keep the upload path usable.
- Cache per session with the existing mechanism, keyed by accession, never by ticker (tickers get reused).

### Dependency injection for tests

The app gets the `EdgarClient` from one factory function (e.g. `_edgar_client()`), so `tests/test_app.py`
can substitute a fake. Follow whatever pattern `test_app.py` already uses for the LLM client; do not invent a
new mechanism if one exists.

## Steps

1. Step 0 spike, with the decision logged.
2. Refactor commit, then gate (dev eval identical).
3. `crosscheck.py` + `tests/test_crosscheck.py`: every badge, the sign-mismatch display, derived → NOT_SCORED,
   and `test_cross_check_never_changes_analysis_result` (deep-compare the result before and after).
4. UI + `tests/test_app.py` additions using a fake client and a pre-rendered fixture PDF: invalid ticker (no
   request made), happy path shows badges, source error shows a message, and the upload path still works.
5. README: the new flow, the local-only/hosted decision, the `SEC_USER_AGENT` setup, a screenshot.

## Acceptance criteria

1. The refactor commit leaves dev eval results identical (`--compare` shows zero deltas).
2. Snapshot unchanged (the cross-check is not part of `analyze()`).
3. In a manual run with AAPL (latest 10-K), badges appear and their counts match what `evals.run --only AAPL`
   reports for the same filing (correct ↔ match, wrong ↔ differs).
4. `grep -rn "xbrl" src/fincopilot/calc src/fincopilot/rules src/fincopilot/mapping src/fincopilot/ai` is empty.
5. An invalid ticker makes zero network requests (tested).

## Stop and ask if

- Moving the eval code changes any eval number.
- The UI needs a change to `AnalysisResult` to show badges (it should not).
