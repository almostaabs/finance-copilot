# T1.2: Hand-labelled Indian set

## Goal

Add about 15 Indian annual reports (Ind AS, FY2023-24) with **human-verified** ground truth to the same
eval harness, so the accuracy numbers cover the app's primary use case, not just US filings.

## Why

Indian listed companies do not offer easily accessible XBRL, so the only truth is a careful hand label.
These reports are also where PDF extraction matters most: for US companies XBRL already exists, which a
reviewer *will* point out. Indian reports are the strongest answer to "why parse PDFs at all?".

## Prerequisites

T1.4 merged.

## Read first

- `evals/score.py`, `evals/truth_xbrl.py`, `evals/run.py` (from T1.1)
- `tier-1-credibility/README.md` (outcome definitions)
- `src/fincopilot/mapping/synonyms.py`: `CANONICAL`, `INDIAN_ALIASES`, `BLOCKED` (for *understanding* the
  concepts only; labellers must not look at them while labelling, see the protocol)
- `src/fincopilot/extract/units.py` (how "crore"/"lakh" and Indian digit grouping like `1,53,670` are parsed)

## Scope

In: the manual truth format, the loader, a label diff tool, the labelling protocol, 15 labelled reports, and
the changes to `score.py` and `run.py`.
Out: any product-code change. Snapshot must show no diff.

## Corpus (fixed)

Non-financial (`bucket=general`), consolidated statements, FY2023-24 annual report:

Infosys, Tata Consultancy Services, Wipro, HCLTech, Reliance Industries, Hindustan Unilever, ITC,
Asian Paints, Maruti Suzuki, Sun Pharmaceutical, Larsen & Toubro, Titan Company, Nestlé India,
Bajaj Auto, UltraTech Cement.

IDs: lowercase short name + `_fy24`, e.g. `infosys_fy24`, `tcs_fy24`, `hul_fy24`. Split with the same hash rule
as T1.1, applied to the ID.

**Getting the PDFs:** download from each company's own investor-relations site only (aggregator sites
rate-limit and may serve altered files). Record the exact URL and the file's SHA-256. If a download is
blocked, **ask the human to download it** and place it in `evals/.cache/india/<id>.pdf`. Never commit PDFs.

## Truth file format: `evals/truth_manual/<id>.json`

Page numbers and figures below are illustrative placeholders, not real values.

```json
{
  "id": "infosys_fy24",
  "company": "Infosys Limited",
  "bucket": "general",
  "currency": "INR",
  "source_url": "https://...",
  "sha256": "…",
  "basis": "consolidated",
  "statement_pages": {"income": [213], "balance": [212], "cash_flow": [215, 216]},
  "labels": [
    {"concept": "revenue", "end_year": 2024, "status": "value",
     "printed_label": "Revenue from operations", "printed_token": "1,53,670",
     "scale": "crore", "page": 213},
    {"concept": "gross_profit", "end_year": 2024, "status": "not_presented"}
  ],
  "labelled_by": ["labeller-a", "labeller-b"],
  "verified_by": null,
  "verified_on": null
}
```

- `page` is the **1-based PDF page index** (what a PDF viewer shows as the page number, not the printed folio).
- `status` is `value` or `not_presented` (the report genuinely does not print this line; e.g. Ind AS income
  statements usually don't show gross profit).
- A concept may have **two** `value` entries for the same year only for equity (see the definitions); both
  are then accepted.
- The base-unit value is **computed by the tool** from `printed_token` + `scale`, never typed by a labeller.
- Only files with a non-null `verified_by` are scored. The rest are reported as "pending verification".

## Concept definitions for labellers (fixed; label exactly this line)

| concept | label this printed line (consolidated statements) |
|---|---|
| revenue | "Revenue from operations". **Never** "Total income" (that includes other income). |
| cogs | "Cost of materials consumed" only if the report prints a single COGS-like line; else `not_presented`. |
| gross_profit | Printed gross profit line; usually `not_presented` under Ind AS. |
| operating_income | A printed operating profit line (e.g. "Profit from operations"); if none, `not_presented`. **Do not compute it.** |
| d_and_a | "Depreciation and amortisation expense" on the income statement. |
| net_income | "Profit for the year" (total, before the split into owners / non-controlling interests). |
| total_assets | "Total assets" |
| current_assets | "Total current assets" |
| cash | "Cash and cash equivalents" on the **balance sheet**. Never the cash-flow statement's closing line. |
| total_liabilities | "Total liabilities" if printed; else `not_presented`. **Do not add up** current + non-current. |
| current_liabilities | "Total current liabilities" |
| short_term_borrowings | "Borrowings" under current financial liabilities |
| long_term_borrowings | "Borrowings" under non-current financial liabilities |
| equity | "Total equity". Also add "Equity attributable to equity holders/owners of the Company" as a second accepted value if printed. |
| operating_cash_flow | "Net cash generated from / (used in) operating activities" (total) |
| capex | "Payments for / Purchase of property, plant and equipment" (incl. CWIP if printed as one line) |

Label every year printed in the statement columns (usually 2024 and 2023).

## Labelling protocol (this is what makes the truth trustworthy)

1. **Two independent labellers** (two subagents, or one subagent plus the human). Each labels the full file
   from the PDF alone.
2. **Labellers must not run the app, read its output, or read `synonyms.py`.** A labeller who has seen the
   app's answer anchors on it, and the eval then measures agreement with itself.
3. Labellers locate statement pages by text search (e.g. `uv run python -c` with pdfplumber searching for
   "Consolidated Balance Sheet"), then **look at the page images** to read the numbers. Text search is only for
   finding pages; reading uses the rendered page.
4. `uv run python -m evals.label_diff evals/truth_manual/drafts/<id>.a.json evals/truth_manual/drafts/<id>.b.json`
   prints every disagreement (value, status, page, printed_label).
5. **The human resolves every disagreement** with the PDF open, writes the final file to
   `evals/truth_manual/<id>.json`, and sets `verified_by` + `verified_on`. An agent must **never** set
   `verified_by`.
6. Drafts are kept in `evals/truth_manual/drafts/` (committed) for auditability.

## Code changes

1. `evals/truth_manual.py`: load a verified file into the same `TruthValue` records as XBRL (compute
   base-unit values with `Decimal`: strip commas, parentheses → negative, `—`/`-` → reject with an error,
   multiply by `SCALE_MULTIPLIER[Scale(<scale>)]`). Add a `not_presented` flag to `TruthValue`
   (`absent: bool = False`) and update `truth_xbrl.py` to always set it False.
2. `evals/score.py`: if truth is `absent` **and** the app produced a mapped value for that concept/year →
   `wrong`, `sub="value_for_absent_line"`. If absent and the app withheld it → it is `no_truth` (excluded).
   Add the tests for both.
3. `evals/label_diff.py` CLI as described, plus a test.
4. `evals/run.py`: `--source xbrl|manual|all` (default `all`). The manual corpus is listed in
   `evals/corpus_india.csv` (`id,bucket,local_pdf`). Report manual results in their own section and totals;
   **never merge them into the XBRL totals**, since they are different truth sources with different reliability.
5. Tests: `tests/test_evals_truth_manual.py` covers Indian digit grouping, lakh and crore, a negative
   token, `not_presented`, an unverified file being skipped, and equity with two accepted values.

## Steps

1. Code changes 1–5, with the gate run (the snapshot must show no diff).
2. Label a **pilot of 3 reports** (Infosys, Reliance, HUL), then human verification, then a run. Review the
   pilot with the human before labelling the rest; the definitions table may need a clarification. Any
   change to the definitions requires re-checking the pilot files.
3. Label the remaining 12. Human verification, then the run.
4. Run `--source manual --split dev` and save `evals/results/baseline_manual_dev.json`.
5. Update `evals/README.md` (manual truth, protocol, definitions) and `docs/ROADMAP_LOG.md`.

## Acceptance criteria

1. 15 truth files exist; the log states how many are verified. Only verified files are scored.
2. Each verified file has both labeller drafts committed, and `label_diff` of the two drafts is recorded in the log
   (count of disagreements resolved).
3. `baseline_manual_dev.json` is committed; manual and XBRL totals are reported separately.
4. `value_for_absent_line` is implemented and tested.
5. The snapshot shows no diff.

## Phase-specific checks

- Evaluator: for 2 verified files, pick 5 random labels each and check them against the PDF page image.
  **Any mismatch fails the phase**, and that file goes back to verification.

## Stop and ask if

- A report does not contain consolidated statements, or reports in a currency other than INR.
- A labeller cannot decide which printed line matches a definition. The definition needs a human decision.

## Subagent split

Two labeller subagents per report (A and B), run in parallel. They must not see each other's output. The
human does verification. A builder does the code changes; an evaluator runs the gate and the spot-check.
