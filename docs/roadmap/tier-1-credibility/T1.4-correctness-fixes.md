## Part A: 10-K unprefixed statements are consolidated

### Design (fixed)

- New pure function in `extract/anchors.py`:
  `def is_sec_annual_report(first_pages_text: str) -> bool`, which returns True when the text contains
  **both** `securities and exchange commission` and `form 10-k` (case-insensitive, any whitespace between
  words, and `10-k` also matching `10‑k` with a non-breaking hyphen). `form 10-q` alone must return False.
- In `locate_statements`: compute it over `"\n".join(doc.page_text[:3])`. Change **only** the branch where no
  CONSOLIDATED candidate exists:
  - if `is_sec_annual_report(...)` and any candidate has `Scope.UNPREFIXED` → `basis = CONSOLIDATED`,
    `scopes = {Scope.UNPREFIXED}`.
  - An explicit `Scope.STANDALONE` candidate is **never** promoted.
  - Everything else is unchanged.
- No new enum members. The decision is evidence-based ("10-K cover page present"), which keeps the rule
  "decided by evidence, never assumption".

## Part B: `implausible_magnitude` red flag

### Design (fixed)

New rule, appended to the end of `RULES`:

- `rule_id="implausible_magnitude"`, `Severity.INFO`
- fired: `"A figure is implausible relative to the rest of the report ({detail})."`
- clear: `"No figure is implausibly large relative to the others."`

Two checks on the **latest period** (and the prior period where needed). Both use mapped or derived
values from `MetricSet.value(...)`:

1. **Year-over-year jump.** For each of `REVENUE`, `TOTAL_ASSETS`, `EQUITY`: if latest and prior are both
   available and both non-zero, compute `max(|a|,|b|) / min(|a|,|b|)`. Fire if ≥ `MAGNITUDE_JUMP_FACTOR = Decimal(100)`.
2. **Asset turnover ceiling.** If `REVENUE` and `TOTAL_ASSETS` (latest) are both available and total assets
   > 0: fire if `revenue / total_assets > ASSET_TURNOVER_CEILING = Decimal(20)`.

Outcome rules:

- If at least one check fires → `FIRED`; `detail` names every check that fired, with concept and year;
  `refs` = the source refs of the values involved.
- If no check fires and at least one check could be evaluated → `CLEAR`.
- If no check could be evaluated (inputs missing) → return an `Unavailable(MISSING_INPUT, ...)` whose `cause`
  is the first missing input's `Unavailable`, so the result is `NOT_EVALUATED` with a root cause.
- Thresholds are module-level named constants next to the existing ones, with a comment giving the
  rationale: *real companies' asset turnover is well below 20; a 100× change in one year in revenue, assets
  or equity almost always means a scale or parsing error, not business reality.*

This is an **INFO** flag. It does not withhold or alter any value; it tells the user to look. Changing
values here would violate "nothing is guessed" in the other direction.

### Steps

1. Implement the predicate `_implausible_magnitude(i: Inputs) -> Maybe[Verdict]`, following the shape of
   `_leverage_increase` / `_revenue_decline`. `Inputs` has the fields `metrics`, `trends`, `reconciliations`,
   `mapping` and `period` (the **latest** period). There is no "prior" field, and **do not use `i.trends`
   for this**: `calc/trends.py` only builds trends for subjects in `RISE_IS`, which does not include
   `total_assets`. Instead add a small private helper `_prior_period(i) -> Period | None` that returns the
   newest period strictly older than `i.period` among `{v.period for v in i.metrics.values}` (None if there is none).
   Values come from `i.metrics.value(concept, period)`, which returns `FinancialValue | Unavailable`.
   Do not add fields to `Inputs`.
2. Append the rule to `RULES`.
3. Find everything that assumes there are ten rules:
   `grep -rn "10\b\|ten\|len(RULES)\|len(red_flags)" tests/ src/ app.py README.md` and update each
   (tests, README "Ten rules", panel grid layout if it hardcodes a count).
4. Tests in `tests/test_rules_redflags.py` (exact names):
   - `test_implausible_magnitude_fires_on_a_100x_revenue_jump`
   - `test_implausible_magnitude_fires_on_asset_turnover_above_ceiling`
   - `test_implausible_magnitude_is_clear_for_golden_us` (a normal report)
   - `test_implausible_magnitude_not_evaluated_names_its_root_cause`
   - `test_implausible_magnitude_ignores_a_zero_denominator` (zero prior → that pair is skipped, not a crash)
   - `test_hostile_pdf_fires_implausible_magnitude`. If `hostile.pdf` cannot fire it (e.g. it has no
     prior period and no total assets), **do not change `hostile.pdf`**: state that in the log and drop this test.
5. Update the rule table in `README.md` and the `docs/KNOWN_ISSUES.md` item #1 (closed by option (b)).

### Expected snapshot / eval changes

- Every fixture gains exactly one line: `flag | implausible_magnitude | <outcome> info`. Its outcome must be
  `clear` or `not_evaluated` for every fixture except possibly `hostile.pdf` (`fired`). Any other line change
  is unexpected, so stop.
- Eval: no change at all (the harness scores values, not flags). Any value change is a bug.
