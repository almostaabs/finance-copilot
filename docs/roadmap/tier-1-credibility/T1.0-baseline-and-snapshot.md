# T1.0: Baseline and regression snapshot

## Goal

Build `scripts/snapshot.py`, which serialises everything the pipeline decides (with AI off) into a
canonical, line-per-fact text form, and commit a snapshot of the current behaviour. From now on, any
change in any number, mapping, flag or reason shows up as a readable diff at the gate.

## Why

The existing 451 tests check specific expectations. They do not tell you when an unrelated change silently
shifts a value somewhere else. A full-output snapshot does, and it doubles as the mechanical proof of
invariant 3 ("AI off → identical to the digit").

## Prerequisites

- `main` is green: `uv run pytest -q` passes, ruff clean.
- If an audit was run, its CRITICAL findings are already fixed (see roadmap README).

## Read first

- `pipeline.py` (the `analyze()` function and what `AnalysisResult` contains)
- `src/fincopilot/types.py` (`AnalysisResult`, `FinancialValue`, `MappingReport`, `MetricSet`,
  `RedFlag`, `ReconciliationCheck`, `Unavailable`, `StatementSet`, `PeriodMap`)
- `tests/fixtures/` (the synthetic PDFs) and `tests/fixtures/real/README.md` + `run_all.py`
- `.gitignore`

## Scope

In: the snapshot script, its test, the committed fixture snapshot, `docs/ROADMAP_LOG.md`.
Out: any change to pipeline behaviour. **This phase must not change a single output.**

## Design (fixed)

- Output is **text, one fact per line, sorted**, so `git diff` is readable. Not pretty JSON.
- `document_id` is a random UUID per run. It must **never** appear in the snapshot.
- Decimals are written with `str(value)`. Never convert to float.
- Committed snapshot: `tests/snapshots/fixtures.snap` (synthetic fixtures only; these are in the repo).
- Local-only snapshot: `.snapshots/real.snap` (real reports, which are not in the repo). Add `.snapshots/`
  to `.gitignore`. It exists so that you can still catch regressions on real reports locally.

### Line format

Each line: `<pdf-name> | <kind> | <key> | <payload>`. Kinds and payloads:

| kind | key | payload |
|---|---|---|
| `basis` | `-` | `StatementBasis.value` |
| `statement` | `income` / `balance` / `cash_flow` | `table_id` + ` pages=` + pages tuple, or `UNAVAILABLE <reason.value>: <detail>` |
| `periods` | `-` | comma-joined `end_year`s from `PeriodMap.ordered`, or `UNAVAILABLE <reason.value>: <detail>` |
| `value` | `<concept>@<end_year>` | `<str(value)> <currency> src=<ref_id or derived:a+b> conf=<extraction_confidence.value>/<analytical_confidence.value>` |
| `value_unavailable` | `<concept>@<end_year>` | `<root reason.value>: <root detail>` |
| `metric` | `<name>@<end_year>` | `<str(value)> <unit.value> conf=<analytical_confidence.value>` |
| `metric_unavailable` | `<name>@<end_year>` | `<root reason.value>: <root detail>` |
| `trend` | `<subject>@<from>-><to>` | `<str(absolute_change)> rel=<str or UNAVAILABLE> <direction.value> <economic.value>` |
| `recon` | `<name>@<end_year>` | `<status.value> delta=<str or UNAVAILABLE>` |
| `flag` | `<rule_id>` | `<outcome.value> <severity.value>` |
| `error` | `-` | `<ExceptionClassName>: <message>` for files the gate rejects (e.g. `scanned.pdf`) |

Where the snapshot needs a root reason, use `Unavailable.root()`. For unavailable metric and value keys,
iterate `result.metric_set.unavailable` (keys are `(name, Period)`). Mapping-level unavailability is already
copied in there by `calculate_metrics`. Verify this by reading `calc/ratios.py::calculate_metrics` before
relying on it.

## Steps

1. **Create `scripts/snapshot.py`** with:
   - `def snapshot_lines(name: str, data: bytes) -> list[str]`: calls `pipeline.analyze(data)` (no `llm`),
     catches `IngestionError` subclasses (from `fincopilot.extract.pdf`) and emits one `error` line. Otherwise
     emits the lines above. Returns them **sorted**.
   - CLI: `--check` (default) and `--update`. For each of the two targets:
     - fixtures: every `tests/fixtures/*.pdf` → `tests/snapshots/fixtures.snap`
     - real: every `tests/fixtures/real/*.pdf` that exists → `.snapshots/real.snap` (skip silently if none)
   - `--check` prints a unified diff (`difflib.unified_diff`) and exits 1 on any difference, 0 otherwise.
     If a snapshot file does not exist yet, `--check` exits 2 with the message "no snapshot, run --update".
   - Make `pipeline` importable: the script runs from repo root, so add the repo root to `sys.path` at the
     top of the script, the same way `demo.py` imports `pipeline` (read `demo.py` to see how).
2. **Generate** the baseline: `uv run python scripts/snapshot.py --update`. Open
   `tests/snapshots/fixtures.snap` and sanity-read it: `golden_us.pdf` values should match the hand-computed
   answers in `tests/fixtures/expected/golden_us.json` (spot-check five).
3. **Determinism check**: run `--check` three times in a row. It must pass every time. If it does not, some
   output is non-deterministic (dict/set ordering, timestamps). Find it and fix it **in the script** by sorting.
   If the non-determinism is in the pipeline itself, stop and ask, because that is a real bug.
4. **Test**: add `tests/test_snapshot.py` with:
   - `test_fixture_snapshot_matches`: runs `snapshot_lines` over all fixtures and compares with the committed
     file. On failure, the assertion message tells the reader to run `scripts/snapshot.py --check` for the diff.
   - `test_snapshot_never_contains_document_id`: assert no 32-hex-char token appears in any line.
   - `test_snapshot_detects_a_changed_value`: monkeypatch one value in a fake `AnalysisResult` (or perturb
     one fixture's output list) and assert the comparison fails.
5. **Real reports (local only)**: if any real PDFs are present locally, run `--update` to create
   `.snapshots/real.snap`. Note in the log which reports were present.
6. **Create `docs/ROADMAP_LOG.md`** with a one-paragraph header explaining the file, then the T1.0 entry.
7. **Update `README.md`**: under Quick start, add the one-line command `uv run python scripts/snapshot.py --check`
   with a short "regression snapshot" description, and update the test count on the Status line.

## Acceptance criteria

1. `uv run python scripts/snapshot.py --check` exits 0 on a clean `main` + this branch.
2. It exits 1 and shows a diff after you temporarily change one threshold in `rules/redflags.py`
   (e.g. `HIGH_LEVERAGE`). Revert afterwards.
3. Three consecutive `--check` runs pass (determinism).
4. `tests/test_snapshot.py` has the three tests; all pass; test count increased by exactly the number added.
5. No 32-hex-char tokens in `tests/snapshots/fixtures.snap`.
6. `.snapshots/` is gitignored; `tests/snapshots/fixtures.snap` is committed.

## Phase-specific checks (in addition to the gate)

- `git diff main --stat -- src/ pipeline.py app.py` is **empty**. This phase changes no product code.

## Stop and ask if

- `analyze()` output differs between two runs on the same PDF.
- An `AnalysisResult` field named above does not exist or has a different shape.

## Subagent split

Builder: steps 1–7. Evaluator: gate + acceptance criteria 1–6, especially criterion 2 (the snapshot must
actually catch a change).
