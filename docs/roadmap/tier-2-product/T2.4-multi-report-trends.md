# T2.4: Multi-report trends

## Goal

Analyse 2–5 annual reports of the **same company** together and show multi-year series (e.g. 2019–2024)
for key concepts and metrics. Each point keeps its source document and cell. Restated figures (a year that
two reports print differently) are shown openly, never merged silently.

## Why

A single report gives two or three years, which is a change, not a trend (the README says so on purpose).
Real analysis needs five years. Restatements are also exactly the kind of thing the product's honesty
should surface.

## Prerequisites

T2.3 merged.

## Read first

- `pipeline.py` (`analyze` returns one `AnalysisResult` per document)
- `src/fincopilot/types.py`: `MetricSet`, `Metric`, `FinancialValue`, `Trend`, `TrendSet`, `Period`
- `src/fincopilot/calc/trends.py` (`calculate_trends`, `EconomicSense` assignment)
- `src/fincopilot/charts.py` (chart spec conventions, and how unavailable values are left out instead of drawn as zero)
- `app.py` (upload flow, the T2.2 ticker flow, tabs)

## Design decisions (fixed; the reasoning is here so nobody re-decides it)

1. **Each report is analysed independently** with the unchanged `analyze()`. The series is built afterwards
   by a new pure module. The single-report pipeline and snapshot are untouched.
2. **Compatibility**. A report joins the series only if its currency equals the first report's and its
   basis equals the majority basis. An excluded report is listed with the reason. Never convert currency.
3. **Same company**. In the ticker flow it is guaranteed (same CIK). For uploads, the user must tick
   "These reports are for the same company", and the UI lists the file names. The app does not guess identity.
4. **One year printed by several reports**:
   - values equal within the half-unit tolerance (use `crosscheck.compare` from T2.2) → one point, "confirmed
     by N reports", source = newest report;
   - values differ → **point uses the newest report's figure** and is marked `RESTATED`, showing every
     report's figure with its source. Reason: the latest filing is the figure the company currently stands
     behind. This is a disclosed rule, not a guess, and the UI must state it wherever the point appears.
5. **Provenance across documents**: `ref_id`s are document-local (`page_P_table_T_row_R`), so they collide
   across reports. Every series point carries `document_label` (file name or `FY2024 10-K`) and
   `document_index` next to the original value object.
6. **Metrics** are taken from each report's own `MetricSet` for its own periods, merged with rule 4. They are
   not recomputed across documents in this phase (average-denominator metrics would mix sources).
7. **Year-over-year changes** between adjacent years in the series reuse `calculate_trends` by building a
   `MetricSet` from the merged points (values and metrics). `EconomicSense` logic stays in one place.
8. **CAGR** (new) for revenue and net income only: when the series has ≥3 years, both endpoints exist, and both
   are > 0. Otherwise `Unavailable` with the reason (e.g. "negative start value: CAGR undefined").
9. Gaps (a year missing between reports) stay gaps. Nothing is interpolated.

## New code

- `src/fincopilot/types.py` (additive):
  ```python
  class PointStatus(Enum): SINGLE = "single"; CONFIRMED = "confirmed"; RESTATED = "restated"

  @dataclass(frozen=True, slots=True)
  class SourcedFigure:
      document_index: int
      document_label: str
      figure: FinancialValue | Metric

  @dataclass(frozen=True, slots=True)
  class SeriesPoint:
      subject: str                 # concept value or metric name
      period: Period
      chosen: SourcedFigure
      status: PointStatus
      alternatives: tuple[SourcedFigure, ...]   # every other report's figure for this year

  @dataclass(frozen=True, slots=True)
  class SeriesSet:
      points: tuple[SeriesPoint, ...]
      trends: TrendSet
      cagr: Mapping[str, Maybe[Decimal]]        # "revenue", "net_income"
      excluded: tuple[tuple[str, Unavailable], ...]   # (document_label, why)
  ```
- `src/fincopilot/calc/series.py`: `def build_series(results: Sequence[tuple[str, AnalysisResult]]) -> SeriesSet`.
  It is pure, with no I/O.
- UI: a **Multi-year** tab, shown when ≥2 reports are analysed.
  - Uploader accepts multiple files (max 5), plus the same-company checkbox. In the ticker flow, the filing
    select becomes a multi-select (max 5).
  - Line charts (revenue & net income; margins), built with the same conventions as `charts.py`. Gaps are gaps;
    `RESTATED` points get a distinct marker, and their tooltip lists every report's figure.
  - A table of years × concepts, where each cell shows the value, a source document label, and a
    restated/confirmed badge. "Show source" uses the T2.3 viewer with the right document's bytes.
  - A CAGR line with its period span, or the reason it is unavailable.
  - An "Excluded reports" callout, when there are any.
- Keep analysis of each report cached separately (by file hash), so adding a sixth year doesn't re-run five.

## Steps

1. Types + `series.py` + `tests/test_calc_series.py`. Build `AnalysisResult`s from the existing fixtures
   (`golden_us.pdf` analysed twice with different labels works for "confirmed"). For restated, gaps, currency
   mismatch and basis mismatch, construct results in-test. Required tests:
   `test_restated_year_uses_newest_report_and_keeps_both`, `test_equal_figures_are_confirmed`,
   `test_currency_mismatch_excludes_report_with_reason`, `test_gap_years_are_not_interpolated`,
   `test_cagr_unavailable_for_negative_start`, `test_cagr_requires_three_years`,
   `test_series_points_keep_document_identity`.
2. UI + `tests/test_app.py` additions (two uploads → tab appears; one upload → no tab; checkbox required).
3. Manual check with real data: 3 consecutive Apple 10-Ks via the ticker flow (or local PDFs). Compare the
   revenue series against the three filings by hand, and note any restatement.
4. README: a multi-year section and screenshot. Update the "Two-period documents…" limit sentence.

## Acceptance criteria

1. Snapshot unchanged; dev eval unchanged (single-report behaviour untouched).
2. All required tests pass; the "can fail" check is done on the restated test.
3. The manual Apple check matches the filings, and is recorded in the log.
4. No code path converts currency or interpolates (reviewed and stated in the log).

## Stop and ask if

- Reusing `calculate_trends` requires changing its signature.
- Two reports from the ticker flow disagree on basis (that suggests a locate bug, not a restatement).

## Subagent split

Builder: step 1, then evaluator. Builder: steps 2–4, then evaluator (who repeats step 3 independently).
