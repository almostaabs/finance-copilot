# T2.3: Source viewer with cell highlighting

## Goal

For any mapped value, show the actual PDF page as an image with the exact source cell outlined, plus a
zoomed crop around it. "Every number traces back to the exact row on the exact page" becomes something a
reviewer *sees* in one click.

## Why

This is the product's signature feature. Provenance tables are convincing to engineers; a highlighted cell
on the real page is convincing to everyone.

## Prerequisites

T2.2 merged.

## Read first

- `src/fincopilot/types.py`: `SourceRef`, `TableRow`, `ExtractedTable`, `NormalizedCell`, `FinancialValue`
- `src/fincopilot/extract/pdf.py`: `_build_table`, `extract_pdf` (both the ruled `find_tables()` branch and
  the `text_grid` fallback branch)
- `src/fincopilot/extract/textgrid.py` in full (`Word`, `text_grid`)
- `src/fincopilot/extract/locate.py`: `stitch_tables` (rows keep their true page)
- `src/fincopilot/extract/units.py`: where `NormalizedCell`s are created (search `NormalizedCell(`)
- `app.py` Provenance tab, and how the uploaded bytes are held in session/cache

## Current state (verified)

No bounding boxes are captured today: `SourceRef` has page/table/row/`col_idx=None`, and `NormalizedCell` has
no position. `ExtractedTable.col_x` holds column left edges only. So this phase has two halves: **capture**
(extraction) and **display** (UI).

## Design (fixed)

### Types (additive, with defaults, so nothing else changes)

- `TableRow`: add `cell_bboxes: tuple[BBox | None, ...] = ()`, aligned with `cells`.
- `NormalizedCell`: add `bbox: BBox | None = None`.
- In `types.py`: `type BBox = tuple[float, float, float, float]  # (x0, top, x1, bottom), PDF points, top-left origin (pdfplumber convention)`.
- Do **not** add a bbox to `SourceRef` (it is row-level and minted in one place; keep it that way).

### Capture

- **Ruled tables**: `page.find_tables()` returns `Table` objects whose `.rows[i].cells` are bboxes (or `None`
  for merged cells), in the same row order that `.extract()` returns text. Pass them into `_build_table`
  alongside the text rows, and filter both lists **in the same comprehension** when blank rows and the header
  are dropped, so they stay aligned. Add an assertion that lengths match.
- **Text-grid tables**: add `bottom: float` to `Word` (from `extract_words`' `bottom`). Change `text_grid` to also
  return, per output cell, the union bbox of the words assigned to it (`None` for an empty cell). **The text it
  returns must be unchanged.** A dedicated test compares text output before and after on every fixture.
- **Stitching**: rows are moved between tables but keep their own `ref.page`; bboxes travel with the row.
  Verify, don't assume: add a test on `stitched.pdf`.
- **Normalisation**: when `units.py` builds a `NormalizedCell` for `(row, col)`, set
  `bbox = row.cell_bboxes[col]` if present, else `None`.

### Display

- New pure module `src/fincopilot/source_view.py`:
  `def render_cell(pdf_bytes: bytes, page: int, bbox: BBox, *, resolution: int = 110) -> tuple[Image, Image]`
  returns (full page with the rectangle drawn, crop of the bbox padded by 60 pt with the rectangle). Use
  `pdfplumber.open(...).pages[page-1].to_image(resolution=...)`, `.draw_rect(bbox, stroke_width=3)`, and
  `.annotated`. Close the page after rendering.
- **Provenance tab**: after the existing page/table/row/raw-text walk for the selected figure, show the crop,
  then the full page in an expander. Caption: "Page P of the uploaded document. The outlined cell is where
  <concept> <year> was read." If `bbox is None`, show: "Position not captured for this cell (merged or
  unusual layout). Page P, row '<label>'." Never guess a rectangle.
- **Values tab**: a "Show source" action per row that selects that figure in the Provenance tab (use
  `st.session_state`; follow the tab/selection pattern already in `app.py`).
- Derived values (EBITDA, FCF, total debt) show their input values' sources instead (one crop per input).
- Cache rendered images per `(document hash, page, bbox)` with `st.cache_data`, max 64 entries.

## Steps

1. Confirm `pdfplumber`'s `to_image` works in this environment (it needs `pypdfium2`, normally installed with
   pdfplumber). If it needs a new dependency, stop and ask.
2. Types (additive defaults). Full gate: everything must pass unchanged at this point.
3. Ruled-table capture + tests.
4. Text-grid capture + `test_text_grid_text_output_unchanged_on_all_fixtures`.
5. Normalisation wiring.
6. **The key correctness test**, `test_every_mapped_value_bbox_contains_its_raw_token`: for every fixture, for
   every mapped `FinancialValue` with a bbox, `page.crop(bbox).extract_text()` contains the cell's digits
   (compare after stripping commas, spaces, parentheses and currency symbols). This proves the rectangle is on
   the right number, not just somewhere plausible.
7. `source_view.py` + tests (returns images of the right sizes, and the rectangle pixels differ from the
   un-annotated page inside the bbox).
8. UI wiring + `tests/test_app.py` additions (the Provenance tab shows an image for golden_us revenue; bbox-None
   shows the fallback text).
9. README: new screenshot of the highlighted cell. Update the Provenance row of the dashboard table.

## Acceptance criteria

1. Snapshot unchanged (bboxes are deliberately not part of the snapshot).
2. Dev eval unchanged.
3. Test 6 passes on every fixture.
4. **Real-report check** (a script, `scripts/check_bboxes.py`, run on all local real reports and 5 rendered
   10-Ks): the share of mapped values that have a bbox, and the share of those passing the test-6 containment
   check. Target: 100% containment for values that have a bbox. Anything below 100% is a bug to fix in this
   phase. Record the bbox capture rate in the log; missing bboxes go to KNOWN_ISSUES with examples.
5. Hosted check: open golden_us sample, click through three values, and the rectangles are on the right numbers.

## Stop and ask if

- Ruled-table bbox rows cannot be aligned with extracted text rows.
- Capturing bboxes changes any extracted text.

## Subagent split

Builder A: capture (steps 2–6). Evaluator gate. Then builder B: display (7–9). The evaluator runs criterion 4
independently and looks at 10 random crops by eye (Read the saved PNGs).
