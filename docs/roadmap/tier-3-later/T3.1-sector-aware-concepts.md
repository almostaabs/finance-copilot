# T3.1: Sector-aware concept sets

## Goal

Stop judging banks and insurers against concepts they do not report. Today a bank shows current assets,
current liabilities, current ratio and gross profit as "unavailable", which is correct but reads as a
failure, and it drags coverage down. After this phase those show as **not applicable for this kind of
company**, and coverage and rules account for it.

## Prerequisites

Tier 2 exit gate passed.

## Decision step (answer first; record the answer in the log)

How is the profile chosen?

- **A. Evidence-based detection** (recommended). A profile is `BANK` only if the located balance sheet has
  **no** current-assets/current-liabilities subtotal **and** the income or balance statement contains at
  least two of a fixed list of literal labels (normalised): `net interest income`, `interest earned`,
  `deposits`, `advances`, `loans and advances to customers`, `provision for loan losses`,
  `allowance for credit losses`. `INSURER` is similar with its own list (`premiums earned`,
  `net premiums written`, `policyholder benefits`, `insurance contract liabilities`, `claims incurred`).
  Otherwise the profile is `GENERAL`. The profile and its evidence (which labels matched) are shown to the user.
- **B. User selects** in the sidebar (default "auto" = A).

Recommendation: A with B as an override. This follows "decided by evidence, never assumption" and still
gives the user control.

## Design (after the decision; this assumes A+B)

1. **Spec change (explicitly authorised by this phase):** add `UnavailableReason.NOT_APPLICABLE =
   "not_applicable"`. Amend the spec with a dated note. This is the only enum change allowed.
2. `src/fincopilot/profile.py` (pure): `detect_profile(statements, normalized) -> ProfileDecision(profile,
   evidence: tuple[str, ...])` with the literal label lists as module constants.
3. `NOT_APPLICABLE_CONCEPTS: dict[Profile, frozenset[CanonicalConcept]]`: BANK → current_assets,
   current_liabilities, gross_profit, cogs; INSURER → current_assets, current_liabilities, gross_profit, cogs.
   The metrics depending on them (current_ratio, gross_margin) inherit `NOT_APPLICABLE` as the root cause.
4. Where the profile applies: after mapping, any of those concepts that is `Unavailable` gets its reason
   replaced by `NOT_APPLICABLE` with the evidence in the detail. **If the report actually printed and mapped
   such a value, keep the value.** Documents beat profiles.
5. Rules: `weak_liquidity` for a BANK/INSURER → `NOT_EVALUATED`, reason `NOT_APPLICABLE`, message "Not
   applicable to banks: no classified balance sheet."
6. UI: KPI cards show "Not applicable (bank)" in a neutral style, distinct from the "unavailable" grey dashed
   style. The profile and its evidence appear in the header.
7. Eval: coverage denominators exclude `NOT_APPLICABLE` records; report the financial bucket's coverage both
   ways (all concepts / applicable only) so the change is transparent.

## Steps

1. Decision logged. Spec amendment + enum member.
2. `profile.py` + tests (JPM-like and insurer-like label sets → profile; a manufacturer → GENERAL; a bank that
   *does* print current assets → keeps them).
3. Wiring (mapping post-step, rules, views) + tests.
4. Snapshot: **expected diffs** are only `value_unavailable`/`metric_unavailable`/`flag` lines for bank-like
   documents changing reason to `not_applicable`, plus a new `profile` line kind (extend `scripts/snapshot.py`,
   add the `profile` line for every document, and state this in the log). General fixtures must show only the
   new `profile | - | general` line.
5. Eval: financial bucket re-run and report regenerated. `wrong` unchanged across all buckets.
6. README + KNOWN_ISSUES updates.

## Acceptance criteria

1. Merchants Bancorp and JPM (dev or local) detected as BANK with evidence shown; Apple as GENERAL.
2. No general-profile document changes any value, metric or flag (snapshot proves it).
3. `wrong` unchanged everywhere.
4. A test proves that a printed and mapped value is never replaced by `NOT_APPLICABLE`.
